# Docs search: MiniSearch, stemmed, with typos and curated synonyms (human asked; details agent)

- Human: the docs site's search is fuzzy and matches synonyms. It finds a page from a typo (`boundry`, `hydartion`, `erorr`), a word's start as it's typed (`hydr`, `serializ`), another form of the word (`boundaries`, `hydrating`), a synonym the page never uses (`ssr`, `exception`, `preload`, `sequential`, `cookie`), and an API name whole, by part or from the concept (`useAtomResult`, `use atom result`, `client error` for `RpcClientError`).
- **[MiniSearch](https://lucaong.github.io/minisearch/)**, built at build time: `build/content.ts` collects each section's prose (code blocks left out, `build/markdown.ts`), serves it as `virtual:docs-search`, its own chunk, about 14 KB gzipped. The dialog starts loading it when the search button is hovered, focused or opened (`components/search.tsx`). Pages and headings are documents; titles count 6×, descriptions 2×, body 1×, a heading's page title 0.5×, and a page 1.5× a heading.
- **Terms**: lowercase, stop words dropped, Porter-stemmed ([`stemmer`](https://github.com/words/stemmer)). The index also keeps each word unstemmed (about 3 KB gzipped) so a word typed past its stem still prefix-matches. Identifiers are indexed whole and by camelCase part.
- **Typos**: MiniSearch's fuzzy search (one typo under 6 letters, two from 6, none under 4), plus each neighbouring-letter swap searched exactly, since Levenshtein counts a swap as two.
- **Synonyms**: a curated map, `src/search/synonyms.ts`, expanded at query time so the index stays small. Each query word scores its best match among itself and its synonyms (synonyms at 0.4×, a phrase divided by its word count), not the sum, and a synonym's scores are scaled so it never outscores the word typed: otherwise a rare API name such as `AtomErrorBoundary` outranks a heading with the word itself. Phrases match their words anywhere in a hit, so phrases of common words (`fetch on render`) are left out, and so are words whose stem collides with another (`serial` and `serialization`).
- The API reference's pages weigh 0.3 (`SearchPage.weight`), and a query that spells an API name puts the heading with that title first ([api-reference.md](./api-reference.md)).
- Every query word must match; when no hit matches them all, hits matching any are ranked by their sum.
- Tests: `src/search/docs-index.test.ts` (typos, prefixes, stems, synonyms, API names, ranking) on a small corpus, and the section text in `build/markdown.test.ts`.
- Lost: Orama (bigger, and its typo tolerance and stemming need plugins for the same result), Fuse.js (no inverted index; scores whole strings, so body text ranks poorly and it has no stemming), Pagefind (indexes built HTML in its own UI and fragments, outside the dialog), indexing synonyms into the index (bigger, and the map couldn't change without a rebuild of the ranking), and the old substring match over titles and headings, which raf-query's site still uses.
