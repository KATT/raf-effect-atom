# A social card per docs page, rendered at build time (human asked)

- Human: every deployed site has Open Graph / Twitter card images; the docs site one per page with its title and section, in the site's branding and logo. Look at raf-query first, then tRPC's `v12` `www`.
- (agent) raf-query ships one static `og.png` for every page, which is what `www` had. tRPC's `v12` branch (`next/www/build/og-image.ts`) renders a card per page in the build, and that's what this follows: `tooling/og-image` lays each card out with [satori](https://github.com/vercel/satori) and rasterizes it with [resvg](https://github.com/thx/resvg-js), as an Effect program.
- (agent) `www`: the `ogImages` Vite plugin writes `og/index.png` for `/` and `og/docs/<slug>.png` for each page (`ogImagePath` in `www/src/seo.ts`), from the page's frontmatter: section above the title, the description, the URL. `pageHead` points `og:image` and `twitter:image` at it with absolute URLs on `site.url`, and `twitter:card` is `summary_large_image`. The dev server renders a card when it's asked for. PNGs are cached in `www/node_modules/.cache/og` by a hash of their SVG; the cards take about a second uncached, so CI doesn't cache them.
- (agent) The look: the logo's near-black (`#0B0B14`) with its orbit drawn large behind the text in its teal → violet, a teal glow bottom left and a violet one top right, a teal → violet bar along the bottom. Inter and JetBrains Mono from `@fontsource`, so the build needs no network. The logo comes from `@examples/kit/lib/logo`.
- Lost: a hand-drawn static card (drifts from the pages); `@vercel/og` functions (the site is static files with no functions); emoji in titles (the fonts carry Latin only, `plainText` drops them).
- Lives in: `tooling/og-image/src/{card,render,vite}.ts`, `www/vite.config.ts`, `www/src/seo.ts`.
