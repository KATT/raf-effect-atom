# The demos show what happens over time (human asked; how is agent)

- **Every demo traces itself** (human: "visualise its features well"). The demo kit records, per demo registry, each request's four moments (client sends, worker receives, worker responds, client settles) and each labelled `AsyncResult` atom's states. The worker reports its two moments over a `ServerEvents` stream RPC in the control group, so the server side is the real server's, not a guess from latency.
- **Atoms are sampled, not subscribed**: a keep-alive atom reads `registry.getNodes()` every animation frame. Subscribing would mount the atoms and change the readers and idle-TTL eviction the demos are showing.
- **Three views of one trace**, beside every demo:
  - _Atoms_: a node per atom (after Kit Langton's [Visual Effect](https://github.com/kitlangton/visual-effect)) lighting `Initial`, `Success` or `Failure` (the tag, or `unknown` for a defect). Waiting is drawn as stripes on the current state, because in `AsyncResult` it's a flag on a result, not a state between them.
  - _Requests_: each request travels from the registry to the worker and back, with the server's time ticking at the worker end.
  - _Timeline_: a lane per atom and per request over the last six seconds, after the lane timelines in the [Effect website](https://github.com/Effect-TS/website)'s Module of the Week posts.
- **Feature visuals** go in the demo itself: a boundary chain that shows which boundary caught which tag, the loader verbs side by side (what blocks navigation, what streams), hydration as a server registry handing results to the browser's without a second request.
- **Accessible**: colours are `--state-*` tokens in `www/src/styles.css`, built on the logo palette with `light-dark()`, and fill shapes while text stays the foreground colour. Motion is CSS transitions and keyframes behind `motion-safe:` / `motion-reduce:`; with reduced motion the timeline moves a page at a time instead of scrolling. Each visual has a text equivalent (a screen-reader caption, or the Queries tab's tables).
- **No motion or sound libraries, no copied code or assets**: the site's shared shadcn components, Tailwind and lucide icons. The inspirations are credited on the docs' credits page.
- **Effect RPC details that matter here**: the worker client's pool lends a worker to one request at a time unless `concurrency` is set, which would serialize requests and let the never-ending `ServerEvents` stream block everything; and `RpcServer` sends a handler defect as a fatal `Defect` that fails every request in flight, so the worker sets `disableFatalDefects` to fail only the request, as over HTTP.
