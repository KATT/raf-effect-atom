# Examples open on CodeSandbox from a generated branch (human asked, agent ported from raf-query)

- Human: link an Examples page from the site's top bar, as raf-query does, with the same CodeSandbox setup. `www/content/examples.md` lists the three apps (source, live URL, Open in CodeSandbox, what each shows), and `site-header.tsx` links it.
- CodeSandbox's synced templates (`https://codesandbox.io/p/devbox/github/<owner>/<repo>/tree/<branch>/<folder>`) open one folder and need no sign-in. A folder of `main` can't reach `examples/.shared/` or `packages/`, so `tooling/codesandbox` writes a standalone pnpm workspace per app, and `.github/workflows/codesandbox.yaml` pushes them to the `codesandbox` branch (commit `chore: sync examples from main (<sha>)`, by github-actions[bot]) after installing and building each one.
- Each copy: `apps/<app>`, plus every workspace package the app depends on, transitively (`dependencyDirs` from `@tooling/vercel-ignore/workspace`), in `packages/<dir name>`. Unlike raf-query, the libraries are copied as workspace packages too, and the sync runs on every push to `main` that touches what it copies instead of after Release: the examples run `main`'s library code, which can be ahead of the version on npm, so a copy pinned to npm could fail until the next release (2026-10-23, after the first releases: kept, since switching would need the sync to wait for Release and the registry). The app's paths into `examples/.shared/` (Tailwind's `@source`) are rewritten to `packages/`. The root has the monorepo's `pnpm-workspace.yaml` with `apps/*` and `packages/*` (keeps the catalog and the Vite+ override), `packageManager` and `engines`; `.codesandbox/tasks.json` (`pnpm install`, then `pnpm dev` with `preview.port` from the dev script's `--port`); `.codesandbox/template.json`; `.devcontainer/devcontainer.json` on `ghcr.io/codesandbox/devcontainers/typescript-node:24`, whose global pnpm switches itself to `packageManager`.
- Vercel deploys every pushed branch of the four projects ([vercel-projects.md](./vercel-projects.md)) as a preview. The branch has `{"git": {"deploymentEnabled": false}}` in each project's root directory (`www/vercel.json`, `examples/<app>/vercel.json`), so its pushes don't deploy (raf-query's branch fails its Vercel builds instead).
- Preview URLs are `https://<id>-<port>.csb.app`: the Vite apps set `server.allowedHosts: [".csb.app"]` (Vite answers 403 otherwise), and Next.js sets `allowedDevOrigins: ["*.csb.app"]` (it blocks `/_next/*` dev requests, the HMR socket included, from other origins). In the source apps, so the copies stay unpatched.
- Not ported: raf-query's npm registry wait (the copies don't install the libraries from npm) and its Next.js build-cache handling (a sync builds three copies in a few minutes).
