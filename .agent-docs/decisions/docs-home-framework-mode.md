# Home page framework switcher (human asked: "steal the component" from raf-query)

- A pill above the hero code switches the home page's samples between **TanStack Start**, **Next.js** and **React Router**, ported from raf-query's `FrameworkModeBar`. It docks in `#hero-code`'s top padding, drifts to the viewport's center as the page scrolls (large screens), sticks under the site header, and leaves with the bottom of `#how-it-works`. The math is `www/src/framework-mode-bar-layout.ts`. The active link is the primary colour, like the site's primary buttons.
- The choice is `?mode=nextjs` or `?mode=react-router` on `/`; TanStack Start omits it (`stripSearchParams`). Links use `replace` and `resetScroll={false}`. An unknown mode reads as TanStack Start (`Schema.catchDecoding`), not a route error. Lost: localStorage and a site-wide preference shared with the docs pages, as in raf-query: the docs' samples are TanStack Start only, so there's nothing for a docs page to switch yet.
- `/` is prerendered once with every mode's panels; a blocking head script sets `html[data-framework-mode]` from `?mode=` before paint, and CSS shows the matching `[data-framework-panel]`. The render calls `syncFrameworkModeAttribute`, which also moves the shared step `id`s onto the visible panel and marks the active pill link as `Link` does (`aria-current`, `data-status`, `active`), because hydration doesn't patch the prerendered default's attributes. The prerender's `filter` skips `?` links, so `/?mode=…` doesn't overwrite `index.html`.
- Below the hero, "How a route loads its data" has five steps per framework: atoms, registry, loader (server component in Next.js), reading, boundaries. The old standalone boundaries section is its last step. Prose differs per framework where the wiring does.
- Samples are `sample:` imports from `www/samples/tanstack-start`, `www/samples/nextjs` (`src/app/issues/[id]/page.tsx` server page, `src/components/issue-page.tsx` client component, `src/app/layout.tsx`) and `www/samples/react-router` (`app/root.tsx`, `app/atoms.ts`, `app/routes/issues.$id.tsx`). The three apps' `issues-client.ts`, `issues.ts` and `boundaries.tsx` are copies of each other (Next.js adds `"use client"`), so a read API change updates the same regions in each.
