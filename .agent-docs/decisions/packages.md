# Two standalone packages, Effect and React as peers (human asked; versioning agent)

- **`effect-atom-boundary`** (`packages/effect-atom-boundary`): typed error boundaries for `@effect/atom-react`. Depends only on `@effect/atom-react`, `effect` and `react`, never on `raf-effect-atom` (human).
- **`raf-effect-atom`** (`packages/raf-effect-atom`): prefetching atoms from route loaders, with a verb per call, and streaming their results to the client. Framework integrations (TanStack Start / Router, Next.js, React Router) are subpath exports, not separate packages. Its read hook uses `effect-atom-boundary`'s claiming primitive through an **optional** peer dependency, so an app has one read hook and the boundary package stays usable alone.
- **`effect`, `@effect/atom-react` and `react` are peer dependencies, never regular ones**, plus `catalog:` devDependencies for the workspace. A regular dependency, even a caret range, leaves deduping to the package manager, and a second Effect splits module-level state (service tags, the default runtime, `Hydration`'s and `AtomRegistry`'s type ids) as well as adding size. Install blurbs list the peers next to the package.
- **Lockstep versions** (agent): both packages share one version and release together, as in raf-query, so one tag and one changelog cover them. Open to revision if the boundary package should release on its own cadence; release-it would then need a config per package.
- Package `exports` point at `./src/index.ts` so workspace consumers need no build; `publishConfig.exports` swaps in `dist`, which `pnpm pack` applies. Built with `vp pack`, which keeps peers external.
