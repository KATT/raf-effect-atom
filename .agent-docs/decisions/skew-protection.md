# Skew Protection: every document response sets `__vdpl`, a stale chunk reloads (agent)

- Skew Protection is on in all four Vercel projects. Vercel sends a request to the deployment it names with `?dpl=`, an `x-deployment-id` header or a `__vdpl` cookie, within the project's max age, and to the latest deployment otherwise. Navigations (`Sec-Fetch-Dest: document`) always go to the latest deployment, cookie or not: check with that header, since `curl` without it is routed by the cookie.
- Each app stamps `__vdpl=<its deployment>` on every document response, at the routing layer, so it's set before the page requests anything: Nitro's `vercel.skewProtection` (TanStack Start, `Path=/`), Vercel's React Router builder (`getSkewProtectionRoute` in vercel/vercel's `packages/remix`, `Path=/`), and a route in `www`'s own Build Output config (`www/build/vercel-output.ts`, `Path=/assets`). Next.js names its deployment on its own requests; its example's `/rpc` fetch sends `x-deployment-id` from `process.env.NEXT_DEPLOYMENT_ID`.
- Vercel follows the first `__vdpl` a request sends, and browsers send the longest path first; a header or `?dpl=` beats the cookie. Builds from 2026-10-23 19:03 to 19:18 UTC set `__vdpl; Path=/assets` from script, which survives reloads and sent every later page's `/assets` files to that deployment (404, as `text/html`). So `www` sets its cookie on `Path=/assets`, replacing that one on the next document, and the TanStack Start and React Router examples build into `/static` (`build.assetsDir`), which it never reaches. The React Router builder only marks `/assets` immutable without `@vercel/react-router`'s preset (React Router 7 only), so that example's files are revalidated instead.
- The cookie is per browser, so the last document load wins across tabs: an older tab's next chunk goes to the newer deployment and 404s. TanStack Router reloads for a route component and React Router for a route module. `www` loads doc content and demo chunks in loaders, so its router reloads too: `defaultOnCatch` and `defaultErrorComponent` in `www/src/components/route-error.tsx`, once per chunk per session under TanStack Router's own session key. Not `vite:preloadError`: it also fires for hover preloads, so it would reload under the pointer.
- Lost: a cookie the page sets from script. It's written after the browser has requested the page's scripts, and it outlives the page: with `Path=/assets`, the next document from a newer deployment requested its scripts from the old one and got 404s, and the page never ran to replace the cookie. A directory per deployment (`build.assetsDir`) with the cookie on it would avoid that, but every deploy would change every asset URL. Also lost: a `base` at the deployment's own `*.vercel.app` URL (cross-origin module scripts need CORS) and `?dpl=` on every import (a query on one module doesn't reach the modules it imports).
- Reproducing: request interception that serves an old deployment's responses on the production host stores their `Set-Cookie` on the deployment's `*.vercel.app` host, so it shows the cookie as missing. Keep a page open on production and click after a newer deployment goes live.
