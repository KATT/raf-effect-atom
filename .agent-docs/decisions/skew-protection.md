# Skew Protection pins a page's requests, not its documents (agent)

- Skew Protection is on in all four Vercel projects. Vercel sends a request to the deployment it names with `?dpl=`, an `x-deployment-id` header or a `__vdpl` cookie, within the project's max age, and to the latest deployment otherwise.
- Next.js names it on its own requests (chunks, RSC fetches). TanStack Start, React Router and the prerendered `www` named nothing: after a deploy, a client navigation imported a chunk only the old deployment had and got a 404. TanStack Router reloads for a route component; React Router reloads the page the click left; `www`'s doc content and demo chunks, loaded in loaders, rendered "Something went wrong!".
- The Vite apps pin `/assets` with the cookie: `pinAssets` (`examples/.shared/kit/src/lib/skew-protection.ts`) sets `__vdpl=<VERCEL_DEPLOYMENT_ID>; Path=/assets` in the browser, and again on `focus` and `pageshow`, since a tab from a newer deployment overwrites it. A chunk import can't carry a header, and a query on one module doesn't reach the modules it imports. Each app's `envPrefix` passes the build's id to the browser.
- `Path=/assets`, not `/`: Vercel routes documents by the cookie too, so with `/` a reload keeps getting the old deployment, which sets its own id again, for the rest of the browser session. Nitro's integration (`vercel.skewProtection`) does that; the TanStack Start example turns it off.
- The browser RPC transports send `x-deployment-id` (Next.js: `process.env.NEXT_DEPLOYMENT_ID`), so a page calls the backend of its own contract.
- `www` reloads for a chunk that's still gone (past the max age): `defaultOnCatch` and `defaultErrorComponent` in `www/src/components/route-error.tsx`, once per chunk per session under TanStack Router's own session key. Not `vite:preloadError`: it also fires for hover preloads, so it would reload under the pointer.
- Lost: a server-set cookie per app (a Build Output route, Nitro config, a React Router `headers` export), three mechanisms where one works and the last document load wins across tabs; a `base` at the deployment's own `*.vercel.app` URL (cross-origin module scripts need CORS); `?dpl=` on every import, which means rewriting each one.
