# One HydrationBoundary import, picked by the react-server condition (human asked)

Human: "In raf query we had some more thought through entrypoints like /rsc and I think we should match how we did that. I think the hydration boundary just automatically changed based on the runtime too". Matches raf-query's [hydration-boundary-one-import.md](https://github.com/KATT/raf-query/blob/main/.agent-docs/decisions/hydration-boundary-one-import.md) and [query-provider-main-entry.md](https://github.com/KATT/raf-query/blob/main/.agent-docs/decisions/query-provider-main-entry.md).

- **`import { HydrationBoundary, RegistryProvider } from "raf-effect-atom"`** everywhere. The main entry's `react-server` condition points at `src/index-react-server.ts`, whose `HydrationBoundary` (`hydration-boundary-react-server.tsx`) is an async server component: given the request's `registry`, it waits for the seed, dehydrates it and renders the client boundary with the state; given `state`, it passes it on. `index.ts` gives the `"use client"` one (`hydration-boundary.tsx`). Both re-export `index-shared.ts`: lint's `import/export` rejects an explicit export shadowing an `export *`.
- **One props type**, a union of `{ registry }` and `{ state? }`, in `hydration-boundary.tsx`. TypeScript doesn't see `react-server`, so both builds type as one component; the client build throws when given `registry`.
- **`raf-effect-atom/rsc` replaces `/next`**, and holds the server-only verbs (`getRegistry`, `prefetch`, `ensure`, `fetch`, `run`, `makeRequestAtoms`). They use only React's `cache` and `cacheSignal`, nothing from Next.js. raf-query dropped its `/rsc` once nothing was left in it; here the verbs are left, because raf-query apps make their own `cache`d client and raf-effect-atom ships it.
- Removed, no aliases (pre-1.0): `HydrateAtoms`, `RegistryProvider` from `/next` and `/react-router`, and `/rsc`'s `dehydrate` (the server boundary does it; `Hydration.dehydrate` stays on the main entry). Not adopted from raf-query: a per-request "sent" set, so nested boundaries each send their registry's atoms, as `dehydrate()` did.
- `/tanstack-router` keeps one build. raf-query's `browser` condition there drops server-only code from browser bundles; not asked for here.
- Tests: `test/rsc.react-server.test.tsx` imports `index-react-server.ts` in the `react-server` Vitest project, where a `vite.config.ts` plugin turns `"use client"` modules into client references as a bundler does. `tooling/rsc-frameworks` builds a page with `@vitejs/plugin-rsc` and checks the HTML, that each atom ran once, and the payload's client references; without the condition it fails on React's "Only plain objects" error. Pack Check resolves the packed main entry with `node --conditions=react-server` (resolution only: importing would run the `"use client"` modules, which a bundler swaps for references).
